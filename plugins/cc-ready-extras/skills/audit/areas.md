# 영역별 점검 기준

영역마다 **꼭 볼 것**을 먼저 확인한다. 하나도 확인하지 못했으면 그 영역은 "확인 못 함"이다. 등급 예시는 기준을 맞추기 위한 것이고, 목록에 없는 문제도 같은 무게로 판단한다.

프로젝트에 자체 규칙(CLAUDE.md, DESIGN.md, 디자인 시스템, 린트 설정)이 있으면 그 규칙이 이 문서보다 먼저다.

---

## 1. 기능

실제로 실행해서 본다. 코드만 읽고 "될 것"이라고 쓰지 않는다.

꼭 볼 것
- README나 CLAUDE.md에 적힌 실행, 빌드 명령이 그대로 되는지
- 핵심 흐름 2~3개를 처음부터 끝까지 (예: 가입 → 로그인 → 저장, 검색 → 상세 → 공유)
- 실행 중 콘솔 오류, 서버 로그 오류
- 잘못된 입력, 빈 데이터, 네트워크 끊김일 때

| 등급 | 예 |
|---|---|
| P0 | 핵심 흐름이 끝까지 안 됨, 빌드 실패, 데이터가 저장되지 않거나 남의 데이터가 보임 |
| P1 | 자주 쓰는 기능의 오류, 콘솔 오류가 계속 남, 잘못된 입력에 하얀 화면 |
| P2 | 드문 경우의 어색한 동작, 불필요한 경고 |

## 2. 디자인

화면을 넓은 화면과 휴대폰 폭(390px 안팎) 둘 다 캡처해서 본다.

꼭 볼 것
- 시각 위계: 화면마다 가장 먼저 봐야 할 것이 가장 먼저 보이는지
- 일관성: 같은 역할의 버튼, 카드, 제목이 화면마다 같은 모양인지
- 간격과 정렬: 정해진 간격 단위를 따르는지, 어긋난 줄이 있는지
- 색과 글꼴: 정해 둔 색(토큰)과 글꼴 크기 단계 밖의 값이 있는지
- 휴대폰 폭에서 가로로 넘치거나 겹치는 곳
- 어두운 화면을 지원하면 그쪽도

| 등급 | 예 |
|---|---|
| P0 | 휴대폰에서 핵심 버튼이 가려지거나 화면 밖으로 나감, 글자가 배경에 묻혀 안 읽힘 |
| P1 | 화면마다 다른 버튼 모양, 위계가 없어 무엇을 눌러야 할지 모름, 정해 둔 색 밖의 값이 여러 곳 |
| P2 | 몇 px 어긋난 정렬, 한두 곳의 간격 차이 |

## 3. 사용성

닐슨의 10가지 원칙으로 본다. 원칙마다 0~4로 적어 두면 다음 비교에 좋다(점수 계산에는 지적만 쓴다).

꼭 볼 것 (원칙)
1. 지금 상태가 보이는가 (불러오는 중, 저장됨, 실패)
2. 사용자의 말을 쓰는가 (개발자 용어, 내부 이름이 화면에 없는지)
3. 되돌리고 빠져나갈 수 있는가 (취소, 뒤로, 실행 취소)
4. 같은 것은 같게 하는가 (화면마다 같은 말, 같은 동작)
5. 실수를 막는가 (지우기 전 확인, 잘못된 입력 막기)
6. 기억하지 않아도 보이는가 (선택지와 현재 위치가 보이는지)
7. 자주 쓰는 사람이 빨리 할 수 있는가 (단축, 기본값)
8. 필요한 것만 보이는가 (군더더기, 반복 정보)
9. 오류가 원인과 다음 할 일을 말하는가
10. 막혔을 때 도움말이 있는가

| 등급 | 예 |
|---|---|
| P0 | 되돌릴 수 없는 작업에 확인이 없음, 오류가 나도 아무 표시가 없어 사용자가 실패를 모름 |
| P1 | 오류 문구가 원인을 말하지 않음, 현재 위치를 알 수 없음, 같은 기능이 화면마다 다른 이름 |
| P2 | 기본값이 아쉬움, 단축 방법이 없음 |

## 4. 접근성

꼭 볼 것
- axe 같은 자동 검사가 있으면 돌린다 (없으면 아래를 직접)
- 키보드만으로 핵심 흐름이 되는지, 포커스가 보이는지
- 글자와 배경의 명암비 (본문 4.5:1, 큰 글자 3:1)
- 이미지의 대체 글, 버튼과 입력칸의 이름(label)
- 누르는 곳의 크기 (휴대폰 24px 이상, 권장 44px)

| 등급 | 예 |
|---|---|
| P0 | 키보드로 핵심 흐름을 못 끝냄, 입력칸에 이름이 없어 화면 낭독기로 쓸 수 없음 |
| P1 | 명암비 미달 본문, 포커스 표시 없음, 의미 있는 이미지에 대체 글 없음 |
| P2 | 장식 이미지의 불필요한 대체 글, 제목 단계 건너뜀 |

## 5. 화면 문구

화면에 보이는 글만 본다. 프로젝트에 문구 규칙이 있으면 그 규칙이 먼저다.

꼭 볼 것
- 버튼이 누르면 무엇이 되는지 말하는지 ("확인" 대신 "저장")
- 오류와 빈 화면 문구가 원인과 다음 할 일을 말하는지
- 같은 대상을 화면마다 같은 말로 부르는지
- 과장, 구호, 번역투, 질문으로 끄는 말("처음이신가요?"), 같은 말 되풀이
- 날짜, 내부 코드처럼 사용자에게 필요 없는 정보

| 등급 | 예 |
|---|---|
| P0 | 문구가 사실과 달라 사용자가 잘못 행동함 (예: 저장 안 됐는데 "저장됨") |
| P1 | 오류 문구가 "오류가 발생했습니다"뿐, 핵심 버튼 이름이 무엇을 하는지 안 알려 줌 |
| P2 | 번역투, 군더더기, 한두 곳의 다른 이름 |

## 6. 코드 구조와 리팩터링 거리

고칠 곳을 찾는 영역이다. "더 깔끔해 보여서"는 지적이 아니다. 실제로 버그를 부르거나 수정을 어렵게 하는 것만 적는다.

꼭 볼 것
- 같은 로직이 세 곳 이상 복사돼 서로 어긋나기 시작한 곳
- 너무 긴 함수와 파일 (한 번에 여러 일을 해서 고치기 무서운 곳)
- 쓰이지 않는 코드, 주석 처리된 코드
- 한 곳을 고치면 엉뚱한 곳이 깨지는 결합 (전역 상태, 순환 import)
- 타입 검사와 린트 결과 (명령이 있으면 실행)

| 등급 | 예 |
|---|---|
| P0 | 타입 검사나 빌드가 실패하는 상태로 남아 있음 |
| P1 | 복사된 로직이 이미 어긋나 버그가 됨, 핵심 모듈의 순환 의존, 수백 줄짜리 함수가 자주 바뀜 |
| P2 | 쓰이지 않는 함수, 이름이 역할과 다름, 린트 경고 |

리팩터링 거리마다 "고치는 법"에 `/cc-ready-extras:refactor <대상>`으로 넘길 대상을 적는다.

## 7. 주석과 문서

꼭 볼 것
- README의 설치, 실행 방법이 지금 그대로 되는지 (1번 기능에서 실행한 결과를 쓴다)
- CLAUDE.md나 AGENTS.md의 명령과 경로가 실제와 맞는지
- 주석이 코드와 어긋난 곳 (함수가 바뀌었는데 주석은 예전 동작을 설명)
- 주석이 "무엇"만 되풀이하고 "왜"가 필요한 곳(이상해 보이는 처리, 우회, 결정)에는 없음
- 공개 함수나 API의 사용법이 어디에도 없음

| 등급 | 예 |
|---|---|
| P0 | README대로 하면 설치나 실행이 안 됨 |
| P1 | 코드와 반대로 말하는 주석, CLAUDE.md의 검증 명령이 틀림, 우회 처리에 이유가 없어 누가 지울 위험 |
| P2 | 코드를 그대로 읽어 주는 주석, 오래된 TODO |

## 8. 테스트

꼭 볼 것
- 테스트 명령이 있으면 실행한다. 통과, 실패, 건너뜀 수를 출력 그대로 적는다
- 핵심 흐름(1번에서 고른 것)을 지키는 테스트가 있는지
- 건너뛰기(skip, only)가 남아 있는지
- 아무것도 확인하지 않는 테스트 (expect 없음, 늘 참)
- 재시도 설정이 실패를 가리는지 (재시도 없이 한 번 더 돌려 본다)

| 등급 | 예 |
|---|---|
| P0 | 테스트가 실패한 채로 남아 있음, 테스트 명령이 돌지 않음 |
| P1 | 핵심 흐름에 테스트가 없음, only가 남아 나머지가 안 돎, 재시도로만 통과 |
| P2 | 같은 것을 확인하는 중복 테스트, 이름만 보고 무엇을 지키는지 모름 |

## 9. 보안

꼭 볼 것
- 저장소에 들어간 비밀값 (키, 토큰, 비밀번호, .env), git 기록 포함 (`git log -p -S` 로 의심 문자열)
- 사용자 입력이 쿼리, 명령, HTML에 그대로 들어가는 곳
- 인증과 권한: 로그인 없이, 또는 남의 계정으로 데이터에 닿는 길
- 의존성 취약점 (`npm audit`, `pip-audit` 등이 있으면 실행, 결과는 실제로 쓰는 경로만 무게를 둔다)
- 외부로 열린 설정 (CORS 전체 허용, 디버그 모드로 배포)

| 등급 | 예 |
|---|---|
| P0 | 저장소에 실제 비밀값, 로그인 없이 남의 데이터 조회, SQL이나 명령 주입 |
| P1 | 실제로 쓰는 경로의 알려진 취약 의존성, 운영에 켜진 디버그 모드, 권한 검사가 화면에만 있고 서버에 없음 |
| P2 | 쓰지 않는 경로의 취약 의존성, 보안 머리글 누락 |

## 10. 성능

꼭 볼 것
- 화면이 있으면 Lighthouse나 비슷한 측정 (휴대폰 기준). 없으면 빌드 산출물 크기
- 큰 이미지, 압축 안 한 파일, 첫 화면에 필요 없는 큰 스크립트
- 목록마다 반복되는 요청이나 쿼리 (N+1)
- 사용자가 기다리는 곳에 표시 없이 오래 걸리는 작업

| 등급 | 예 |
|---|---|
| P0 | 핵심 화면이 휴대폰에서 10초 넘게 걸림, 요청이 끝없이 반복됨 |
| P1 | LCP 4초 넘음, 수 MB 이미지가 첫 화면에, 목록 N+1 쿼리 |
| P2 | 작은 최적화 거리 (글꼴 미리 불러오기, 캐시 머리글) |
